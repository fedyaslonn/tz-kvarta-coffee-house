# Кварта - лендинг кофейной обжарки

Проект состоит из лендинга на Next.js, API на FastAPI, PostgreSQL для хранения заявок и Telegram-уведомлений. Фронтенд размещается на Vercel, API - на Railway, а управляемая база PostgreSQL - в Neon.

## Как распределялись таски

Основную реализацию выполнял самостоятельно: проектировал схемы в Marshmallow и модели данных, писал FastAPI-эндпоинты, интегрировал Telegram-бота, собирал компоненты фронтенда и форму заявки. Также самостоятельно подготовил Dockerfile, компоуз и настройки pre-commit, линтеры, миграции и другие конфиги. После завершения отдельных задач я отправлял код ИИ на ревью и доработку: просил проверить логику, обработку ошибок, крайние случаи и читаемость реализации, добавлять комменты для читаемого описания функций, эндпоинтов, скриптов.

ИИ помогал с ревью кода, подсказками по настройке деплоя в Vercel, Railway и Neon Console, а также с проработкой отдельных фич интерфейса: вариантов дизайна, CSS-стилей и генерации графики для сайта, работой с регулярками. Результаты предложений всегда проверялись.

## Ошибки и что удалось заметить

На одном из этапов ИИ предложил слишком тяжёлый Docker-образ для фронтенда. Это заметили при просмотре состава образа и зависимостей, после чего я упростил Dockerfile и уменьшил его. Во время ревью также обнаружился сгенерированный, но мертвый код; удалял его, чтобы не усложнять проект. Руками проверял все фичи, валидацию, создание заявки, генерацию уведа в тг.

## Почему PostgreSQL

PostgreSQL выбрана как БД для заявок, потому как есть хороший опыт работы с ней, надежна для транзакций параллельных.
